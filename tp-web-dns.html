DNS & serveur web

Donner un nom à un service.

Ce TP explique le chemin parcouru lorsqu’une personne saisit une adresse dans son navigateur : le DNS retrouve le bon serveur, puis Apache affiche le site.

DNS Bind9Apache2HTTP
Le besoin

Une adresse simple

Personne ne veut retenir une suite de chiffres pour accéder à un site interne.

La réponse

Le DNS oriente

Il associe un nom clair au serveur qui héberge réellement le site.

Le résultat

Un site accessible

Le navigateur reçoit la page demandée via une adresse facile à utiliser.

Le fonctionnement

Une requête, trois acteurs.

Un service web devient simple à utiliser lorsque chaque maillon sait exactement quoi faire.

Navigateurwww.entreprise.local
Serveur DNStrouve la bonne adresse
Serveur Apacheretourne la page

Un nom mémorisable mène au bon service

Ce que j’ai fait

Rendre le web compréhensible.

01

Créer le répertoire

J’ai configuré une zone DNS dédiée à l’entreprise et vérifié que le nom du site renvoie vers la bonne machine.

02

Préparer le serveur web

J’ai installé Apache, placé une page web et vérifié que le service peut répondre aux navigateurs.

03

Tester l’expérience finale

Le test s’est fait comme un utilisateur : saisir une URL claire et constater que la bonne page s’affiche.

Ce que ce TP m’a appris

Derrière une simple adresse web se cache une coopération entre le réseau, le DNS et le serveur web. Comprendre ce parcours aide à diagnostiquer beaucoup de problèmes d’accès.
